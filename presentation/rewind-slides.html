Before an import · A recurring check for the person responsible for updates

You asked for new prices. Keep the other values.

1. Bring two CSVsToday’s export and your proposed import are inspected in separate gVisor containers on Vultr.
2. Say what should changeChoose the intended fields and a numeric change limit, such as 25% for prices.
3. Hold mistakes outBlank overwrites, unexpected fields, large price changes and unknown IDs stay out.
4. Approve exact cellsReview every included update. Both files, your rules and exact selection are bound to approval.
5. Execute the importBuild the approved CSV and apply it to a disposable copy using updates to existing records by ID.
6. Check and downloadFresh workers inspect both outputs. Every approved and protected value must match before download.

Executed example: 22 ordinary price updates included. 26 unwanted cell changes and one unknown ID excluded. All 24 records and payment statuses retained. Fixed preflight checks use no model calls.

After a mistake · Real AI investigation and recovery on Vultr

The agent investigates. You approve the repair.

1. Inspect versionsBring the good copy, incident checkpoint and today’s file. Trusted gVisor workers read each version.
2. Investigate the mistakeVultr Inference writes diagnostic code that actually compares the three copies in its own sandbox.
3. Protect later editsThe controller checks the proposal. Observed overlaps stay unchanged. You approve individual cells.
4. Write the recoveryA second Vultr call writes the exact repair. Generated code receives the cell mask, not acceptance answers.
5. Run on copiesThe repair executes in another gVisor container. Your originals stay unchanged.
6. Verify every valueA fresh worker reads the result. The controller verifies approved cells, protected values and cleanup.

Executed recovery: 117 prices restored; all 127 invoices kept, including seven newer records, twenty payment updates and three prices edited again afterward. CSV and SQLite are supported.
