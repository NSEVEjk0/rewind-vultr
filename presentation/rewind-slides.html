Why Vultr is part of the work

Try a recovery on copies. Check every change.

1. InspectTrusted gVisor workers on a Vultr VM read both SQLite copies.
2. GenerateVultr Serverless Inference receives schema and selection metadata, then writes the recovery program.
3. RunA separate temporary gVisor container runs the program on copies.
4. CheckA fresh worker reads the output. The controller compares every selected and unselected value.

The model receives no invoice rows, database files or actual selected IDs. Its program gets read-only database copies, with no controller credentials. The independent checker stays outside its container.

Download opens after the data checks and removal of all temporary containers pass. This live run used one model request and five isolated worker runs.

Vultr VM + Serverless Inference · No network in workers · Read-only inputs · Fixed resource limits
