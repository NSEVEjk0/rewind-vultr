Vultr deployment design

Try the recovery on copies. Check every change.

1. InspectFixed gVisor workers read the two database snapshots.
2. GenerateVultr Serverless Inference receives schema and selection metadata, then writes an attempt.
3. ExecuteA separate gVisor container runs the attempt on read-only inputs and a temporary output.
4. VerifyA fresh trusted worker reads the output. The controller checks selected and protected values.

The generated program does not receive the acceptance checks. Database rows, files, and actual selected IDs are not sent to the model.

Download requires a matching recovery contract and confirmed removal of every sandbox. The deploy package targets an existing Vultr VM; live deployment and model execution are pending.

No network · nonroot user · pinned image/runtime · CPU, memory, PID, time and output limits
